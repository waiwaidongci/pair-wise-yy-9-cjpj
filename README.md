# 蓝晒洗水回用与残留放行

运行：

```bash
npm start
```

访问 `http://localhost:3040`。可用 `PORT` 改端口、`WASH_DB` 改数据文件（默认 `data/cyanotype-wash.json`，落盘走临时文件 + rename 原子写入）。

## 业务文件划分

| 文件 | 职责 |
| --- | --- |
| `routes.js` | 入口层：HTTP 路由、参数校验、编排判定与存储 |
| `rules.js` | 判定层：开洗水质、换水取样、放行、更正失效的纯规则 |
| `store.js` | 存储层：洗槽/水批/洗程台账、JSON 落盘、幂等重放表 |
| `page.js` | 页面视图（开洗、换水/取样/放行操作、洗槽与履历筛选） |
| `server.js` | 薄装配：HTTP 服务 + 上述三层接线 |

## 规则要点

- **开洗**填写：底片编号、水批、电导率（≤800 µS/cm）、银离子（≤0.5 mg/L）、滤芯号、操作者。
- 水批过期、银离子高于 0.5、电导率超过 800 或滤芯被占用时，洗程**只转待换水，不占洗槽**（202 + 原因清单）。
- **同张底片洗片结束前不能开第二洗程**（冲突 409）；相同 `requestId` 重放**返回首条结果**（含首次 HTTP 状态，响应带 `replayed`）。
- **换水**后进入检测中：由开洗/换水操作者**之外的另一人**，**每隔 30 分钟**连续取样登记银离子与滤芯压差。
- 最近连续 2 次取样银离子均 ≤0.1 mg/L、压差均 ≤10 kPa 才可**放行**回用；不达标继续换水重测。
- **更正水批、滤芯或水源**会让放行失效：清空取样、释放洗槽、回到待换水重新计算，更正前版本留档；旧版经 `GET /api/washes/:id/versions/:v` **只读**查看，已结束洗程整体只读。
- 页面洗槽占用、待换水队列、洗程履历全部来自 `GET /api/state` 单一数据源，浏览器刷新后一致。

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 洗槽占用、水批、阈值与全部洗程（页面唯一数据源） |
| POST | `/api/washes` | 开洗（支持 `requestId` 幂等） |
| POST | `/api/washes/:id/change` | 换水登记 |
| POST | `/api/washes/:id/samples` | 连续取样（另一人、间隔 30 分钟，可带 `at`） |
| POST | `/api/washes/:id/release` | 残留放行判定 |
| POST | `/api/washes/:id/finish` | 洗片结束，释放洗槽与滤芯 |
| PATCH | `/api/washes/:id` | 更正（水批/滤芯/水源触发放行失效） |
| GET | `/api/washes/:id/versions/:v` | 旧版只读快照 |
